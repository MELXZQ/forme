# 供应商、采购、支出与物流操作手册

本阶段为本地管理。人工登记表示你已核实的事实；TEST 表示测试；循环自动生成的是应付义务。系统没有连接银行、支付、承运商或域名服务，不会执行付款、退款、续费或查询外部物流。

入口：http://127.0.0.1:3000/admin/business 。沿用已有管理员登录；后台导航提供 Suppliers、Purchases、Expenses、Recurring、Logistics、Permissions。所有保存都需填写原因；错误会显示在表单，成功显示 Saved successfully。别人刚修改同一记录时需刷新后重试。

## 供应商和采购

1. **Suppliers → New supplier**：填写内部编号、名称、默认币种及可选联系人、网址，按 **Save supplier**。详情 **Add SKU source** 将内部 SKU 对应到供应商商品编号、采购链接；同一 SKU 可登记多个来源。**Edit / revise** 可修改资料或勾选 Archived，保留历史采购。
2. **Purchases → New purchase**：选择供应商、负责人、收货仓库、下单时间、预计到货区间和币种；添加 SKU、数量、单价、供应商编号。金额输入正常货币单位，如 `3.25`；系统保存整数分。国内运费和其他已包含费用进入采购总额，折扣不能超过总价。
3. 草稿保存不加库存、不产生付款。详情 **Confirm purchase** 确认后生成唯一关联待付支出。通过详情关联支出进入付款管理。**Edit / revise** 修改确认后的约定须填写原因；已有收付款时勾选已检查历史。已收货或已分配包裹的数量不能直接减到不足，超发应先授权修订采购。
4. **Warehouse acceptance** 登记真实验收：选择可选包裹、填写唯一验收参考号、实际时间和原因，再逐行填写可售与不可售数量。采购页和包裹页使用同一个服务；同一次物理验收务必复用同一参考号和包裹，不另编新号。无物流交付可以不选包裹，但明确写明当面交付等来源。
5. 例：约定20件，实际验收18件，其中17件可售、1件破损：填 `17 / 1`，剩余2件继续待履行。签收按钮不会替你完成验收。验收、库存流水与进度同事务保存。
6. **Close remainder / shortage**：`CANCEL` 取消未执行且未占用的数量并修订应付；`SHORTAGE` 明确关闭少货差异，保留原有费用约定。均需原因，已有付款时需检查是否另行退款。它们都不会虚构入库或资金收付。
7. **Dispatch supplier return**：填实际发出的可售/不可售件数，选择后续约定。`REFUND` 记录应退款期限；`REPLACEMENT` 增加补发承诺；`NO_FURTHER_OBLIGATION` 不增加后续义务。实际发出才减少库存；退款仍要到支出登记，补发仍要重新验收。退货不会自动恢复旧库存。
8. **Close / cancel purchase**：只有剩余承诺为0才可 CLOSED；已执行、已有实付或包裹的采购不能无条件 CANCELLED。Acceptance history、Supplier returns、Parcels 和 Audit timeline 保留发生时间、录入时间及修订。

## 支出、现金和凭证

**Expenses → New expense** 填用途、分类、收款方、负责人、计划日、应付日、金额币种、账户别名、渠道以及预期交付/服务结果和期限。不要填写银行密码、完整卡号或网银凭据。列表底部可维护 Expense category；采购确认自动创建的支出总额须回到原采购修订。

- **Record payment / refund / reversal**：PAYMENT 为实际付款，REFUND 为实际收到退款，CONFIRMED 为已核实，FAILED 为明确失败。填实际时间和唯一外部参考号，人工为 MANUAL；TEST 不进入真实汇总。可多次部分付款/退款，币种须与该支出相同。退款不能超过实际净付款。
- 错误记录使用 REVERSAL 关联原记录、输入原金额并注明原因，随后另记正确记录。历史不可删除或覆盖；同一原记录只冲正一次。存在依赖退款时需先处理退款记录再冲正原付款。
- **Confirm service outcome** 单独填写交付或实际服务生效证据。付款不等于域名续费生效；采购收货结果从验收推导，不在支出重复确认。
- **Set refund expectation** 填约定应退总额及期限，它不会生成已到账记录。**Cancel obligation** 只取消符合条件的义务，不能抹掉实付历史。
- **Link existing fee**：`INCLUDED_COMPONENT` 引用原采购已经包含的费用；`INDEPENDENT` 是另行创建的独立支出。物流只引用这些费用，不能因多处显示重复汇总。
- 私有凭证区 **Upload private evidence** 支持 JPEG、PNG、WebP：单文件最大8MB、每次最多5张、每对象最多20张。检查真实内容并重编码，不接收 SVG、HTML、PDF。**Load attachments** 后通过授权下载查看；凭证不会成为公开商品图片。

Expenses 筛选支持搜索、日期口径（创建/应付/实付）、分类、供应商、负责人、币种、付款/结果状态、关联对象、金额范围和异常，按 **Apply filters** 后参数保留在 URL，可刷新、后退。金额筛选字段若标有 minor units，输入整数分。列表排序、分页与 **Export CSV** 使用当前筛选；CSV 金额列明确使用最小货币单位。

汇总按原币分别列出义务、实付、退款、净流出和待付。实付日期筛选中的现金按实际发生时间统计，冲正按冲正发生日调整。报告币种为 AUD，人工汇率格式为“1原币单位 = 多少AUD”，必须填日期与来源；缺汇率明确标未知，不当作0，不直接相加不同币种。这是支出/现金流统计，不是利润或已售商品成本。

## 循环支出

**Recurring → New recurring** 设置服务商、金额、DAY/WEEK/MONTH/YEAR、每N期、原始锚点、时区、提醒天数、宽限期和预期结果。ACTIVE 启用，PAUSED 暂停，ENDED 结束。任务在提醒窗口生成每期待付支出，绝不生成真实付款。

月末不存在的日期取当月最后一天，下期仍用原始锚点：1月31日→2月末→3月31日。2月29日年度规则在非闰年取2月28日，闰年恢复2月29日。时区支持北京与墨尔本，实际时间另行保存。

**Edit / revise** 只影响未来尚未生成周期；已生成的每期金额和已付款历史不被改写。暂停/结束后恢复 ACTIVE 必须填写 **Explicit resume date**（今天或以后）。补历史使用 **Backfill past periods → Preview missing periods**，检查范围及数量再保存，单次最多100期；已存在周期不会重复创建，大批历史逾期通知按规则汇总。

PROVIDER_AUTO 表示服务商可能自动扣费；没有回执/人工核实仍为待核实，不能猜测余额不足或认定成功。进入 Generated periods 对应支出分别登记实付和服务结果。

## 统一物流

**Logistics** 同时列出现有调拨、订单发货、退货记录与新包裹；Source 列说明来源，业务汇总行与包裹明细不可作为两次发货相加。**New parcel** 选择运输类型、来源业务单、负责人、仓库、发收件信息、承运商/追踪号、SKU数量及预计时间。同一采购/调拨/订单可有多个包裹；重复追踪号需解释合理复用原因，未把追踪号设为全球唯一。

供应商入库包裹按采购剩余数量分配；订单配送引用已有履约服务的发货结果；退供应商、顾客退回包裹引用已经登记的对应实物退货。当前不改变原有整单发货规则，也不新增另一套库存扣减。旧调拨和订单行可打开原运营详情进行实际收发货。

**Record transport event** 手工登记发出、运输中、SIGNED、异常等，记录真实发生时间、来源和原因。修改 ETA 留审计；确认 LOST / RETURNED 需要授权及明确原因。TEST 只写测试事件，不改变实际状态。SIGNED 只表示人工登记签收，验收状态独立。

供应商入库详情的 **Warehouse acceptance** 与采购页完全同源。其他物流通过原调拨、履约或退货页面处理库存。无物流的普通手动入库继续用 Stock & orders 的原入口，明确来源及原因，不编造追踪号。

列表可组合查类型、业务号/追踪号、SKU/商品、仓库、承运商、负责人、运输/验收状态及发出/ETA/签收/验收日期、逾期、差异。逾期按目的地时区和原通知宽限规则判断，“未登记送达”并不声称实际未送达。

## 权限、通知和本地任务

Owner 可管理全部模块和 Permissions。墨尔本仓管默认只访问其履约所需物流与不含成本的墨尔本采购验收；不能查看供应商联系方式、采购成本、全部财务、财务凭证或循环规则。Owner 可授予 procurement、finance、recurring、logistics 附加能力；循环修改同时需要 finance 和 recurring。北京操作仍受已有所有者边界约束。Viewer 保持只读。服务端直接请求也校验权限。

Related notifications 链到原通知中心，复用指定确认人、版本、置顶与处理历史。采购、支出、包裹共享一条采购迟到事项；付款失败与货损仍是独立问题。自动异常置顶须满足原来的全部确认及解决/有权限说明关闭规则。

双击根目录 **Start Website.command** 会启动数据库、网站和每分钟的预留释放/通知任务；该任务现在同时生成循环义务并检查付款、结果、退款和物流。只运行 `npm run dev` 时另开终端运行 `npm run orders:worker`。不要重复启动多个本地工作进程。手工补查：`npm run notifications:check`；任务成功、错误与范围见通知任务状态。停机恢复按业务状态补查，唯一键防重。

## 备份与恢复

停网站和 worker、保持数据库运行，执行 `npm run db:backup`。备份包含 database.dump、整个 uploads（包括隐藏的 `.private-business` 私有凭证）与私有 `.env.local`。同时保留源码、public/assets、锁文件和迁移。GitHub 仅备份代码，不备份数据库或上传凭证。

用同大版本 PostgreSQL 在独立、已确认空的库恢复，复制上传目录到新的私有目录，临时环境指向它们，核对迁移、数量、权限、图片和凭证后再决定切换；具体命令见 [现有技术手册](operations-technical.md)。不要对正式库执行 reset、--clean 或覆盖目录。本次已验证停机重启持久性，尚未进行整套异机备份恢复演练。
