## 本轮实现

保留现有 Next.js 项目、商城布局、CSS、轮播、人物滚动动画、筛选 URL 和即时更新交互。没有重建前端。原先尚未提交的筛选和文档改动保留。

同一个项目新增 PostgreSQL + Prisma 服务层、受保护的 `/admin`、Better Auth 管理员认证、真实图片上传及媒体访问接口。公开页面和接口读取数据库，不在连接失败时回退模拟数据。

现有示例迁入后共有 16 个商品、5 个分类、2 个系列、23 个媒体记录、3 张轮播和 5 个人物分类标签。SKU、价格、库存、上下架、首页推荐、系列和首页配置均可从后台保存。新品推荐顺序独立于上架时间排序。分类采用单层主分类，系列允许多选；人物标签文案沿用目标分类名称。

运行版本：Node.js 24.22.2、npm 11.19.1、Next.js 16.4.5、React 19.3.1、TypeScript 5.9.3、PostgreSQL 17.11、Prisma ORM/Client/pg adapter 7.10.1、Better Auth 1.7.17、Zod 4.6.7、Sharp 0.35.5。

集成验证覆盖：

1. 应用账号不是超级用户，没有建库和建表权限；不能读取或修改 Prisma 迁移历史。
2. 未登录用户对全部管理资源的直接 GET/POST 请求返回 401；公开管理员注册返回 404。
3. Better Auth 登录成功，Cookie 包含 HttpOnly 和 SameSite=Lax；非管理员请求返回 403。
4. 已登录写请求缺少允许的 Origin，或使用外站 Origin，返回 403。
5. 两张真实 PNG 上传后转换为 WebP，使用服务器生成的存储键；未公开引用的图片对顾客返回 404。
6. SVG、MIME 与文件内容不一致、上传数量过多被拒绝。
7. 创建两个尺码的草稿，公开搜索和详情不泄露草稿。
8. 小数金额、负库存、重复 SKU 被拒绝；唯一冲突导致的多表创建完整回滚。
9. 上架后公开 DTO、两个 SKU、From 最低价和首页推荐正确；公开商品不包含管理状态、创建时间或首页内部排序字段。
10. 修改价格、库存、图片顺序和替代文本后，公开数据和图片立即更新；仍在引用的媒体删除返回 409。
11. 分类、系列、新品排序、优惠、搜索、分页正常读取存储数据。
12. 首页轮播、人物图片、裁切和标签坐标修改后立即反映到公开配置，测试结束恢复原内容。
13. 归档、停用分类、没有启用 SKU 的商品不公开。
14. 停用管理员后访问被拒绝；退出后原会话不能继续管理。
15. 本地登录失败限制生效，超过限制返回 429。

## 启动、管理员与备份

日常启动和完整命令见 [README](../README.md)。当前本地入口为 http://127.0.0.1:3000 和 http://127.0.0.1:3000/admin。

没有默认管理员密码。请在本地项目终端执行 `npm run admin:create`，自行隐藏输入密码；不需要在聊天中提供。验证用管理员已移除。

数据库位于 `.local/postgres/data`，图片位于 `.local/uploads`，密钥位于 Git 忽略的 `.env.local`。应用使用普通 `forme_app`；迁移单独使用 `forme_migrator`。运行时图片、数据库和备份没有放入源代码或构建包。

已在暂停网站写入时成功运行 `npm run db:backup`。最终迁移后的备份为 `backups/2026-11-05T06-03-06-760Z/`，含数据库自定义格式 dump、图片目录及私密环境配置。已验证备份命令成功；没有对现有数据库执行覆盖恢复演练。

## 本阶段范围与未验证事项

- 没有真实支付、正式订单、退款、顾客注册、物流、积分、评价；演示购物袋不预留或扣减库存。
- 没有云服务、公开部署、对象存储、复杂权限体系或分布式限流。登录限流是明确用于单进程本地开发的内存限制。
- 后台提供图片排序及 SKU 图片关联；详情沿用原先的主图布局，没有另外重建复杂图片画廊。
- 手机检查是桌面浏览器视口模拟，未在实体手机上测试；未通过操作系统实际切换减少动态效果，未验证公网 HTTPS/代理及多实例环境。
- 本地正式构建和接口经过检查；日常管理请使用 `npm run dev`。生产 Cookie 配置要求 HTTPS，不把本地 HTTP 接口测试视为生产部署认证验证。
- 列表当前针对本地小目录：SKU 价格和优惠推导后在服务层排序分页；后台商品上限 200 条，媒体上限 500 条。规模扩大时应改为 SQL 聚合分页及后台分页。
- 未实现多人编辑冲突处理和后台审计日志。后续订单服务需独立保存商品/SKU 金额快照，事务性预留库存，并对支付回调做签名校验、幂等处理和订单状态机。
