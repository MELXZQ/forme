# Home 工作台

管理员登录后的默认页面为 `/admin`。原有 **My work** 保留在 Workspace 下；订单、Stock、采购、物流、支出和商品管理入口不变。

## 开始使用

双击项目中的 `Start Website.command`，打开 <http://127.0.0.1:3000/admin> 并使用自己的账号登录。Home 不是对外商城首页，也不会执行付款、发货或库存调整。

顶部显示当前日期、个人时区和当天 UTC 偏移量。沿用通知中心的个人时区设置：Australia/Melbourne 或 Asia/Shanghai；未设置时使用墨尔本。墨尔本夏令时由系统时区规则计算，不写死为 UTC+10。

## 默认布局与权限

| 角色                | 首次打开的组件                                                                |
| ------------------- | ----------------------------------------------------------------------------- |
| Owner               | 今日销售、待发货、墨尔本库存关注、通知与置顶、物流动态、近 7 天销售、近期支出 |
| Melbourne warehouse | 待收货、待发货、待补发、库存异常、通知与置顶                                  |
| Viewer              | 墨尔本库存关注、库存异常、通知与置顶                                          |

组件目录以当前服务端权限为准。仓管默认没有销售或支出数据；既有额外业务授权可开放相应组件，不会自动改变默认布局。Home 不授予新权限。非 Owner 的库存配置仅显示墨尔本。

权限变更后，下一次请求立即按最新角色与授权检查；已撤销的组件不能通过直接接口请求取得数据，页面刷新时也会移除。页面可见时最多约两分钟自动复查，切回页面会补查。单纯显示已加载的网页不等于仍有服务端访问权限。

## 自定义布局

1. 点击 **Customise layout**。此时显示的是未保存草稿，业务链接暂停点击，防止编辑时误跳转。
2. 展开 **Add widgets**，查看名称、说明和标为 Layout preview 的布局预览，再点 Add。预览中的符号不是实际业务数据。
3. 电脑拖动卡片的 **Move** 手柄排序；也可点上移、下移。手机直接使用上移、下移。键盘 Tab 定位按钮，Enter 操作，移动后焦点留在该组件手柄，状态文字播报新位置。
4. 在卡片编辑区选择允许的尺寸。库存关注可选仓库；Owner 可添加多个库存组件分别观察墨尔本、北京或两仓。每个实例有独立 ID 与配置。其他组件不允许无意义重复。
5. 点击 **Remove** 移除可选组件。通知与置顶是核心组件，只允许中、大尺寸，不能移除。
6. **Save layout** 保存到自己的数据库设置，刷新和退出重登后保留。**Cancel** 恢复编辑前的已保存布局。
7. **Restore defaults** 只替换编辑草稿，仍需保存；保存前可取消。

每人最多 12 个组件。刷新数据不会覆盖正在编辑的顺序、尺寸或配置。多标签页同时保存时，较旧草稿会收到冲突提示；先取消加载最新版本，再编辑保存。

桌面使用三列，小、中、大分别占一、二、三列。平板使用两列，中尺寸适应一列，大尺寸占两列，减少空洞。手机统一一列，保持用户顺序。旧版本或损坏设置会安全恢复；失去权限的组件被隐藏，核心通知仍保留。页面会说明自动调整，可再次保存。

## 指标含义与跳转

每张卡片的 **What this includes** 可以展开详细口径。数字有各自的链接，不把整张卡片做成一个容易误触的链接。

| 组件 / 指标            | 口径与点击结果                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Today’s sales          | 按个人时区的今天，使用既有经营统计的成功付款事件时间。AUD 商品成交额为折扣后、退款前，排除运费；现有系统没有单独收取税额。只纳入 REAL 订单与 REAL 成功付款事件。点击进入相同付款日、时区和真实范围的经营统计。                                                                                                    |
| Awaiting dispatch      | 当前所有 REAL、已记录成功付款、已付款且未完成发货的订单，不限创建日。超时数沿用当前发货时限、暂停和工作日规则。分别进入相同条件的订单列表。                                                                                                                                                                       |
| Stock watch            | 启用 SKU 且商品未归档。低库存使用 Stock 中已保存且启用的对应仓库阈值；可售为 0 也包含关闭提醒的 SKU。因此两数独立、可能重叠，不能把缺货全部说成低库存的子集。点击带仓库、有效 SKU 及低库存/零可售筛选。                                                                                                           |
| Notifications & pinned | 今天首次生成的通知，加上之前生成但仍置顶的事项；置顶优先，同一通知只出现一次，遵循原通知对象级权限和可识别的数据来源。                                                                                                                                                                                            |
| Parcel activity        | 仅计物流页中的 PARCEL 运输记录，不将订单/调拨摘要计为包裹，也不将一条记录的 packageCount 个箱数计为多条。已发出/在途为 DISPATCHED/IN_TRANSIT；预计今天到达按记录的 ETA 结束日期且到达未完成；逾期沿用既有宽限、验收状态和业务时区规则。链接固定 record unit=PARCEL 并带对应条件。没有运输记录显示无数据。         |
| Last 7 days            | 个人时区最近 7 个日历日，包含尚未结束的今天。与今日销售共用付款事件及金额口径。点击柱形或日期进入当天明细统计；展开 Daily values 查看文字表格。没有付款记录的日期显示空档，不伪造历史零值或曲线。                                                                                                                 |
| Upcoming expenses      | 今天待付与未来 7 天待付分别展示；未来 7 天固定为明天至第 7 天，不含今天。待付为 OPEN 义务减去已确认的非测试付款，并按存储的到期日筛选。AUD/CNY 等分开列出，没有换算或跨币种相加。无到期记录显示 Nothing due。异常数是有未解决、仍有效、可见异常提醒的支出记录数，不是提醒条数。链接带相同日期、状态、币种及来源。 |
| Awaiting receipt       | 北京→墨尔本调拨中 SENT/PARTIAL 且仍有待接收数量的调拨记录，单位为调拨，不冒充包裹或采购收货数。点击进入待收货调拨筛选。                                                                                                                                                                                           |
| Awaiting replacement   | 现有可见售后范围内 REAL 订单的补发申请，已批准/执行中/失败且补发未发货。单位为申请；点击带相同条件的补偿列表。                                                                                                                                                                                                    |
| Stock exceptions       | 墨尔本有效 SKU 中既有收货/盘点差异标记，以及待盘点审核的 SKU 数。历史收货差异可能在处理后仍留存，不能称为实时未解决异常数量。点击进入相同 Stock 标记筛选。                                                                                                                                                        |

Home 不改变订单、库存、现金或物流的既有计算方式。新增的列表筛选也可在业务页继续修改或清除。

## 通知与置顶的处理

中卡显示最多 3 条，大卡最多 6 条。顶部始终显示匹配总数和 **pinned not shown** 未展示的置顶数量；**View all** 打开同日、同范围的通知中心。未显示不代表没有其他置顶。

摘要含类型、等级、原因、生成时间、负责人、当前版本确认进度和置顶状态。点击打开右侧详情抽屉，可查看首次与最新检查数据、建议动作、关联业务记录、确认人员和历史。

抽屉直接复用通知中心详情和服务端操作。打开表示个人已读；**Confirm current version** 只确认知悉，不会解决异常。解除置顶仍受原多人确认及异常终结规则约束。业务处理需进入关联页面。Esc 或关闭按钮退出，焦点回到原通知；手机全宽展示。

## 加载、错误与测试范围

- **Updating…**：正在读取，该组件显示独立状态。
- **Last successful update**：该组件最近一次成功读取的时间。
- 失败显示错误和 Retry；其他组件继续显示。保留旧值时明确提示可能过期，不把失败当成 0。
- 没有付款事件的历史订单不补造付款时间；未知来源或缺失事件会显示不完整提示。没有销售记录与已知零销售不同。
- 页面 **Refresh** 刷新全部；卡片右上按钮仅重试该组件。可见页面约每 2 分钟刷新，隐藏页面停止定时读取；同浏览器其他后台页面保存成功后会通知 Home 更新。没有外部跟踪服务。
- Home 固定为 REAL 记录范围，排除可识别的 TEST/UNKNOWN 销售、关联费用、运输和通知。库存、调拨及未标注来源的手工记录沿用所属工作区，不凭名称猜测是否测试。
- 3002 的 **TEST WORKSPACE — isolated sample database** 明确表示整个数据库是合成样例。样例库内也保留 REAL/TEST 记录区分，以验证排除逻辑；这里的 REAL 标签不代表已发生真实交易。日常库 3000 不写入这批测试样例。

## 本次数据与实现

继续使用 Next.js、TypeScript、Prisma/PostgreSQL、Better Auth 和现有 Base UI 下拉组件，没有增加依赖。新增迁移 `202611060004_admin_home` 在原个人通知设置中增加布局版本、修订号和 JSON 配置，只保存布局，不保存业务指标或凭据。

主要文件：

- `src/lib/home-layout.ts`：允许的组件、尺寸、配置、角色目录和默认布局。
- `src/server/home/service.ts`：个人布局、最新权限核对、各业务服务聚合和独立错误处理。
- `src/app/api/home/[[...path]]/route.ts`：会话、来源验证、16 KiB 请求限制和 no-store 响应。
- `src/components/home/`：网格、编辑、刷新、图表和状态。
- `src/components/notifications/NotificationDetail.tsx`：通知中心与抽屉共用详情。

不新增环境变量，布局随既有数据库备份。安装这次代码后执行 `npm run db:generate`、`npm run db:migrate`；不执行数据库重置。

## 当前可靠数据边界

未启用跨币种换算汇总、独立税额、箱件数量总计、历史缺失付款补算和仅依靠名称判断的测试筛选。库存差异复用已有标记，没有可靠的统一“未解决库存异常”生命周期，因此明确称为差异标记。没有为这些能力展示假数字。

自动刷新是浏览器轮询加本地标签页通知，不是跨设备实时推送。已保存布局可跨浏览器使用；真实手机、辅助读屏软件及长期大数据量压测尚需单独验证。
